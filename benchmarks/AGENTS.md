# GenesisBench Scoped Working Agreement

These rules apply to `benchmarks/` in addition to the repository working agreement.

## Instrument Boundary

- Keep Cold Acquisition, Open Agent, Genesis-Adapted, and Embedded Local tracks isolated. Never aggregate incompatible profiles, epochs, scaffolds, or context conditions into one rank.
- Public fixtures are commissioning and conformance material, not evidence of temporal cleanliness or frontier capability.
- Held-out payloads, salts, oracles, canaries, private prompts, and evaluator internals never enter model context, tracked public artifacts, logs, corpus stores, or language examples.
- Benchmark code cannot change GenesisCode semantics, grant capabilities, select training data, promote outputs, or authorize a release.
- Model output is untrusted candidate material. Deterministic acceptance, obligation, policy, provenance, license, resource, and independent-review gates remain authoritative.

## Campaign Discipline

- Predeclare the exact repository snapshot, task epoch, scaffold, adapter, model/revision claim, reasoning profile, budgets, capabilities, retry policy, and analysis plan before inference.
- One declared attempt means one attempt. Preserve failures, invalid runs, timeouts, partial traces, and negative results; never retry, resume, filter, or repair them invisibly.
- Bind complete run records and artifacts by content identity. Scoring and replay must work without the target model or mutable provider state.
- Do not let a target model author or admit tasks in the active epoch. Keep task authority, custody, execution, scoring, analysis, and publication roles separable and auditable.
- Training/evaluation transfer requires the explicit BQ-7/BQ-8 firewall and a reviewed promotion record. Benchmark rank alone never admits a trajectory.

## Changes And Evidence

- Extend existing benchmark schemas, profiles, and negative-control matrices before adding another authority or entrypoint.
- Treat task lineage, not context variants or repeated attempts, as the independent unit unless a predeclared analysis proves otherwise.
- Every useful failure must be classified as language, documentation, diagnostics, tooling, policy, runtime, performance, or model reasoning before proposing a product change.
- Run the benchmark-specific guards named by the roadmap execution manifest. Never hand-edit generated fixtures, protocol bundles, cards, or reports.
- A benchmark release must remain independently useful and reproducible without Genesis Foundry or a Genesis Model package.
